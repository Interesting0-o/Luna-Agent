## 一、核心理念

### 1.1 一句话定义

> Luna 的数学引擎不是情感模拟器，而是**情感的外部因果骨架（External Causal Skeleton）**——为 LLM 的生成提供跨时间一致的情感因果结构。

### 1.2 类比：演员与剧本

| 层次 | 类比 | Luna 中的对应 |
|------|------|---------------|
| **演员** | LLM | 单轮情感表达的天才 |
| **剧本** | 数学引擎 | 确保角色行为连贯的因果结构 |
| **导演笔记** | state_formatter | 将因果结构翻译为演员可理解的提示 |
| **排练** | 时间衰减 | 两场戏之间的状态恢复 |

一个演员不需要被解释"悲伤的系统动力学"，他只需要知道"你现在应该悲伤"——但**如果剧本本身没有因果一致性，演员的表演就会时好时坏**。这正是纯 LLM 方案的困境。

### 1.3 对 CRITIQUE.md 的回应

CRITIQUE 的三条核心指控以及我们的回应：

| 指控 | 回应 | 证据 |
|------|------|------|
| 情感不可编码为连续向量 | 我们不是"模拟情感"，而是"编码情感的因果传递结构"——这与情感本身的连续性无关 | O-U 过程是残差情感动力学的标准统计模型（Oravecz et al., 2009），已在心理学纵向数据中验证 |
| OCC 理论不可靠 | Luna 使用 Bowlby 依恋理论（防御剖面）+ 残差 O-U 过程（动力学），**不依赖 OCC** | 2024-2025 年混合架构研究（PCM-LLM, eBICA+LLM）同样使用独立于 OCC 的认知架构 |
| LLM 涌现情感更优 | LLM 缺乏"时间上持续的、因果结构化的情感状态"——这是 2025 年多项研究的共识 | PERSIST 框架 2025, SENTINEL NeurIPS 2025, Affective Residue 2025（详见下文 §2） |

**存续条件**（来自 CRITIQUE 原文）→ 我们的路线：
> *"核心价值是'可解释的生成前导'而非'更好的生成'——你站在与 LLM 互补而非竞争的位置。"*
>
> → **已采纳**。我们正是这样定位的。

> *"学术定位是'角色设计工具'而非'情感模拟器'"*
>
> → **已采纳**。数学引擎的参数化控制面板是核心价值。

> *"目标不是'可信'而是'确定性'"*
>
> → **已采纳**。确定性 + 可审计的因果链是我们的护城河。

## 二、证据基础：为什么混合架构是正确答案

### 2.1 LLM 的情感一致性有架构性缺陷

**PERSIST 框架（arXiv 2508.04826, 2025）**
- 25 个开源模型（1B-685B），200 万+ 次响应
- 仅问题重排就使测量的人格偏移约 **20%**
- 400B+ 模型在 5 点量表上标准差仍 > 0.4
- 结论：LLM **缺乏实现真正行为一致性的架构基础**

**SENTINEL（NeurIPS 2025, San Diego）**
- 情感幻觉以**振荡式突发**出现，非线形累积
- 负面文本特别容易被"中和"
- 少数高情感词不成比例地驱动漂移

**Affective Residue（Zenodo, 2025）**
- 未加工的情感上下文在记忆密集型模型中**毒性累积**
- 触发"杰基尔与海德式"情绪破裂（Affective Rupture）
- 应对方案：上下文衰减窗口、校准摩擦、身份框架

**Sentipolis（CMU, 2025）**
- 诊断 LLM 代理的 **"情感失忆症"（Emotional Amnesia）**
- 方案：连续 PAD 情感表示 + 双速情感动力学（快速评价/慢速反省）

**核心结论**：如果 LLM 真的拥有情感，它不应该在 8 轮对话内就系统性丧失一致性。实际上 LLM 作为 stateless 模型，**每轮对话都从零开始推断情感状态**——这不是"拥有情感"的特征，而是"善演的戏剧演员"的特征。

### 2.2 2025 年学术界正在转向混合架构

| 架构 | 年份 | 来源 | 控制器 | LLM 角色 |
|------|:----:|------|--------|----------|
| **PCM-LLM** | 2025 | Paris-Saclay | 投射意识模型 | 语义推理 + 语言生成 |
| **eBICA + LLM** | 2024 | MEPhI | eBICA 认知架构 | 语言理解 + 回应生成 |
| **Talker-Reasoner** | 2024 | Google DeepMind | Reasoner（系统 2） | Talker（系统 1，对话） |
| **Nadine** | 2025 | 社会机器人 | PAD 情感模型 | GPT-4 推理 + 生成 |
| **情感 ODE 门控** | 2025 | CTRNN + PINN | 神经 ODE | Token 生成引导 |

**PCM-LLM（Université Paris-Saclay, 2025）**
PCM（投射意识模型）作为核心控制器，管理感知、情感、想象、决策和规划。LLM 作为语义子处理器，解释和语言化内部信念。在 3D 战略游戏中，PCM-LLM 在竞争任务中**大幅领先纯 LLM 基线**，且 LLM-only 代理在所有认知条件下表现平淡（"flat, mediocre performance"）。

**eBICA + LLM（Pattern Recognition and Image Analysis, 2024）**
最精确地描述了混合架构的分工——论文原话：
> *"LLMs recognize emotional coloring in utterances but don't understand the logic of emotions."*
> *"Cognitive architectures model emotional dynamics but need help with meaning."*

即：LLM 能识别情感"颜色"，不理解情感"因果逻辑"；认知架构能建模情感动态，需要 LLM 帮助理解语义。

**DeepMind Talker-Reasoner（Google, 2024）**
直接映射 Kahneman 双系统理论到两代理架构：
- **Talker（系统 1）**：快速、直觉、自然对话
- **Reasoner（系统 2）**：慢速、推理性、信念更新与规划
- 通过共享记忆通信，Reasoner 异步更新信念

### 2.3 工业界反例其实在支持混合路线

CRITIQUE 引用 Replika/微软小冰从规则转向 LLM 作为"工业界否定规则引擎"的证据。

但 Replika 的实际架构分析（2025 年专利分析）揭示：
- Replika **仍使用结构化人格提示骨架 + 关系模式系统（Friend/Mentor/Partner）**
- 关键缺陷恰恰是：情感基调在推理时**从对话历史重构**，而非以持久化结构化状态持有
- 结果：情感连续性浅、对模型变更敏感、检索窗口截断时崩溃
- **这正是 Luna 的架构设计要解决的问题**

工业界的转向不是"从规则到纯 LLM"，而是**从纯规则到混合架构**——只是不同公司的混合比例不同。Luna 选择了比 Replika 更高的"因果骨架"权重，这在 2025 年的学术共识下反而有前瞻性。

### 2.4 你的实际架构已经验证了混合模式

Luna 的实际管线：

```
perception(LLM) → state_engine(数学) → state_formatter(规则) → llm_node(LLM)
```

这不是"数学引擎控制一切"，而是：
- **LLM（perception）**：从文本提取情感信号——LLM 擅长的语义理解
- **数学引擎**：将情感信号演化为因果结构化的状态——数学引擎擅长的确定性演化
- **LLM（llm_node）**：在因果轨道内自由表达——LLM 擅长的自然生成

每层做自己能做最好的事。这是 2025 年混合架构研究的**标准模式**。

## 三、路线图

### Phase 0 — 验证数学引擎的边际价值（当前，2 周）

**目标**：用实验证明数学引擎的存在是否产生可感知的质量差异。

**行动**：
- [ ] 实施 A/B 实验（参见 [EXPERIMENT_A_B.md](EXPERIMENT_A_B.md)）
- [ ] 三组条件：A = 完整引擎、B = LLM 自报状态、C = 无状态
- [ ] 自动指标（跨轮连续性、表面-内部分歧度）
- [ ] LLM-as-Judge 盲评
- [ ] 小规模人工评估

**决策点**：基于实验结果决定路线走向（详见 EXPERIMENT_A_B.md §6 决策树）。

**风险**：如果 A ≈ B 且 A > C，数学引擎有正价值但不是不可替代。如果 A ≈ C 或 B > A，需要立即重新评估路线。

---

### Phase 1 — 感知层精度工程（Phase 0 之后，2-3 周）

**目标**：解决 Whitehill 批判——量化并提高 DeepSeek 刺激提取的精度。

**行动**：
- [ ] 构建标注测试集：100 条用户输入 × 7 维刺激强度的**人工标注**
- [ ] 测量 DeepSeek 提取的精度：均方误差、方向正确率（是否符号正确）、维度混淆矩阵
- [ ] 根据测量结果决定优化策略：
  - 如果方向正确率 > 90%：Whitehill 风险可控，继续使用当前感知方案
  - 如果方向正确率 < 80%：需要改进——选项包括感知 prompt 迭代、多模型投票、few-shot 示例增强
- [ ] 实测置信度元数据的有效性：高置信度样本的精度是否确实高于低置信度样本

**输出**：
- 感知层精度报告（量化指标）
- 改进后的感知 prompt（如需要）
- 置信度校准方案（如需要）

---

### Phase 2 — 架构精简与叙事重构（Phase 0-1 并行，3-4 周）

**目标**：基于 Phase 0 的实验结果精简数学引擎，同时重构项目的对外叙事。

**行动**：

#### 2A 架构精简（根据实验方向）

如果 A > B（数学引擎有显著正价值）：
- [ ] 识别冗余维度（基于 PCA 或贡献度分析，移除贡献 < 5% 的维度）
- [ ] 简化最重的约束（当前 11 条约束中哪些可以降级为"建议"而非"强约束"？）
- [ ] 评估防御代谢成本等 P0 修复是否值得投入

如果 A ≈ B（数学引擎有正价值但可替代）：
- [ ] 将数学引擎设计为**可选模块**——默认使用 LLM 自报，用户可选择启用数学引擎获取确定性和可调性
- [ ] 保留数学引擎的核心参数暴露给高级用户（角色设计工具定位）
- [ ] 简化维护最低必要集的耦合规则

#### 2B 叙事重构

- [ ] 项目 README 重写：移除"模拟情感"表述，替换为"为 LLM 角色扮演提供情感因果骨架"
- [ ] CLAUDE.md 更新项目定位
- [ ] 设计文档体系更新：所有 md/ 文件检查是否与新的叙事一致
- [ ] 对外沟通策略：强调**确定性、可审计性、可控性**，而非"更好的情感"

---

### Phase 3 — 长程一致性强化（Phase 2 之后，4-6 周）

**目标**：利用数学引擎的持久化能力解决 LLM 在长程对话中的情感失忆问题。

**行动**：
- [ ] 记忆系统接入管线（目前 `memory_inject_node` 和 `memory_summery_node` 已实现但未接线）
- [ ] 情感-记忆耦合：记忆检索时考虑当前情感状态的相似性（不仅语义相似性）
- [ ] 长程一致性实验：50+ 轮对话，比较有/无数学引擎的情感漂移量
- [ ] 引入 Affective Residue 检测：当累积情感债务超过阈值时触发恢复行为

---

### Phase 4 — 确定性控制工具（Phase 3 之后，持续）

**目标**：将数学引擎的核心价值——确定性和可控性——产品化。

**行动**：
- [ ] 参数化控制面板：暴露 Traits 和关键耦合参数作为角色设计工具
- [ ] 状态可视化：实时显示 8+3+7 维状态轨迹（由数学引擎的确定性保证才有意义）
- [ ] 场景回放：给定初始状态 + 用户输入序列，确定性重现整个状态演化
- [ ] 约束违规报告：每次运行时报告哪些约束被接近违反（防退化监控）

## 四、成功标准

### 技术成功标准

| 维度 | 指标 | 通过线 |
|------|------|--------|
| **一致性** | 跨轮状态演化方差 | 数学引擎方差 < LLM 自报方差 20% 以上 |
| **口是心非** | 表面-内部分歧度 | 数学引擎分歧度显著高于 LLM 自报（d > 0.5） |
| **感知精度** | DeepSeek 方向正确率 | > 85%（对抗 Whitehill 批判的基本线） |
| **长程保持** | 50 轮后角色一致性 | 保持初始设定的 80% 以上（vs LLM 无状态的 < 50%） |
| **确定性与可复现** | 相同输入 → 相同状态轨迹 | 100%（vs LLM 自报的随机性） |

## 六、不做的事（明确排除）

以下方向经评估后**排除在当前路线之外**：

1. **纯 LLM 端到端方案**（放弃因果骨架）→ 排除理由：PERSIST 2025 证明 LLM 在 8 轮内就丧失一致性
2. **传统有限状态机对话树** → 排除理由：非线性动力学的表现力远超硬编码状态转换
3. **热力学情感模型（v2.0 非线性）** → 已剥离至 `md/THERMODYNAMIC_AFFECTIVE_MODEL.md`，待数学引擎价值验真后再考虑
4. **特质演化系统** → 已剥离至 `md/TRAIT_FROM_MEMORY.md`，同上

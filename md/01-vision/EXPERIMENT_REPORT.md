## 1. 实验设计概要

### 1.1 动机

CRITIQUE.md 中提出的最致命指控：

> *"LLM 的涌现情感表征已被证明比任何手工工程更丰富、更可信，'数学可解释'就变成了以牺牲质量为代价换取'我知道数字在变'。"*

本实验的目标：**量化数学状态引擎相对于纯 LLM 方案在情感连续性、角色保真度和"口是心非"表达上的增量价值。**

### 1.2 实验架构

```
用户输入 → [感知] → [状态更新] → [状态格式化] → [LLM生成] → 回复
                         │
                    ┌────┴──────────┬──────────┐
               A_full(引擎)    B_*(LLM推断)   C_none(无)
               A_no_def(无防御)  B_scratch/B_context
```

### 1.3 实验条件定义

| 代号 | 名称 | 管线 | 研究问题 |
|:----:|:----:|:----:|:---------|
| **A_full** | 完整数学引擎 | 4 步管线（防御→反馈→动力学→表面） | 基线——当前生产环境 |
| **A_no_def** | 引擎无防御 | 跳过 Bowlby 防御剖面 | 防御剖面是否产生可测量差异？ |
| **B_scratch** | LLM 自报（无上下文） | LLM 每轮从零推断状态 | 纯 LLM 方案能否替代引擎？ |
| **B_context** | LLM 自报（有上下文） | 注入上一轮 state_desc | 给 LLM 状态记忆能否修复连续性？ |
| **C_none** | 无状态基线 | 跳过一切状态处理 | 最底层基线（状态注入是否有用？） |

关键设计：条件 B 的**状态推断调用与回复生成调用分离**（独立 `model.invoke()`，temperature=0.3），防止状态泄漏。

### 1.4 评估指标

| 指标 | 类型 | 计算方式 |
|:----|:----:|:---------|
| 跨轮状态连续性 | **自动** | 相邻轮次状态向量的余弦相似度 |
| 表面-内部分歧度 | **自动** | `||surface - internal||` L2 范数 |
| 极端值频率 | **自动** | 状态值落在 [-1.0, -0.8] ∪ [0.8, 1.0] 的比例 |
| Hurst 指数 | **自动** | R/S 分析法，衡量状态演化的结构程度 |
| 角色保真度 | **定性** | 回复是否符合"高傲、依恋焦虑、口是心非"的设定 |
| 回复自然度 | **定性** | 从对话角度看回复是否自然不做作 |

## 3. 核心发现

### 发现 1：数学引擎的连续性不可替代

| 条件 | 内态连续性 | vs 引擎差距 | Cohen's d |
|:----:|:---------:|:-----------:|:---------:|
| **A_full** | **0.9996** | —（基准） | — |
| A_no_def | 0.9997 | 无差异 | -4.46 |
| **B_context** | **0.9249** | -7.5% | +1.28 |
| **B_scratch** | **0.6031** | -39.7% | +3.01 |
| C_none | 1.0000 | 完美（无变化） | -21.68 |

**解读**：
- 数学引擎的状态演化是因果连续的（每轮变化幅度 ~0.03%）
- LLM 自报（B_scratch）每轮状态跳跃 ~20-50%，缺乏跨轮一致性
- 给 LLM 上一轮状态（B_context）将连续性从 0.60 提升到 0.92，**但仍与引擎有 8% 差距**

### 发现 2：状态上下文大幅改善 LLM 自报（但不够）

```
B_scratch → B_context 的改善：
  连续性: 0.6031 → 0.9249  (+53%, Cohen's d=2.23, 强烈显著)
```

给 LLM 注入上一轮状态描述作为上下文，让 LLM 状态推断有了"锚定"——不再每轮从零开始推论。这是 prompt 工程对纯 LLM 方案的最有效改进，但：

B_context 的代价：
- **极端值率从 0% 激增到 17.5%**（LLM 倾向于情绪饱和）
- **表面中性率从 47% 骤降到 1.4%**（LLM 几乎从不输出中性状态）
- **表内分歧度从 1.49 膨胀到 2.32**（LLM 高估内心-表面差距 55%）

### 发现 3：LLM 状态推断存在系统性偏差

| 偏差 | 引擎 (A) | LLM (B) | 含义 |
|:----|:--------:|:-------:|:-----|
| 极端值率 | **0.0%** | 17.5% | LLM 过度使用极端值 |
| 表面中性率 | **47%** | 1.4% | LLM 从不中性 |
| 表内分歧度 | **1.49** | 2.32 | LLM 高估口是心非程度 |
| Hurst | 0.50 | 0.50 | 两者均无长期记忆（短序列限制） |

**解释**：LLM 在没有数学约束的情况下倾向于输出"明显的"情感——每轮感受都强烈、外显、不隐藏。这偏离了角色设定（高傲+回避=表面克制），也偏离了真实人类对话（大部分时间情感中性）。

### 发现 4：防御剖面影响内容而非数值

| 指标 | A_full | A_no_def | Δ | 显著性 |
|:----|:-----:|:--------:|:-:|:------:|
| 内态连续性 | 0.9996 | 0.9997 | -0.0001 | 无 |
| 表内分歧度 | 1.4929 | 1.4952 | -0.0023 | 无 |
| 极端值率 | 0.0% | 0.0% | 0% | 无 |
| **回复口吻** | **口是心非** | **直白** | **明显** | **定性显著** |

详见 §6 机制分析。

### 发现 5：DeepSeek 感知 100% 成功

| 感知模型 | 成功率 | 说明 |
|:--------:|:------:|:------|
| Ollama qwen2.5:7b | **0%** | JSON 格式输出持续失败 |

## 6. 防御剖面的实际作用机制

### 6.1 防御做了什么

Bowlby 防御剖面的数学形式：

```python
inner_stimuli = stimuli + hyperactivation  # 放大内心感受
outer_stimuli = stimuli × deactivation     # 压抑外在表达
```

### 6.2 实际修改量级

以"月下誓约"角色（attachment_avoidance=-0.60）为例：

```
Deactivation (d):  [0.004, 0.002, 0.0002, ...]  → 几乎为零
Hyperactivation (a): [0.99, 0.01, 0.83, ...]    → 仅少数维度有效
```

- 因为角色回避度强烈负值（-0.60），deactivation 几乎不激活
- Hyperactivation 仅对 closeness_stimulus 有显著放大（约 +0.20）
- **防御对刺激的平均修改量：约 0.03**
- **耦合项对状态的驱动量级：约 0.20**
- 防御效应仅为耦合效应的 **~15%**

### 6.3 为什么连续性不变

防御是一个**确定性偏置函数**，而非动态调制：

```
有防御:     h_t = h_{t-1} + dt·(耦合 + f(Δ_raw))
无防御:     h_t = h_{t-1} + dt·(耦合 + Δ_raw)
差异:       dt·(f(Δ_raw) - Δ_raw) = dt·bias(profiles, Δ_raw)
```

bias() 对给定输入是固定的。这相当于给状态轨迹叠加了一个**固定的滤镜**：

- 每帧颜色改变（防御修改了 Surface 的绝对值）
- 帧间变化模式不变（连续性测量的是轮间相似度）
- 但影片"看起来"不一样了（回复内容因 state_desc 变化而不同）

**用余弦相似度类比**：如果每轮状态都同时加一个常数向量 c，余弦相似度不变。

### 6.4 防御的真正作用位置

防御修改的是 **Surface 的绝对值**（不是动态模式）：

```
Surface 差异（有防御 vs 无防御）:
  Sharpness:  -0.57 vs -0.52, Δ=0.05  ← 最大差异维度
  Warmth:     -0.05 vs -0.03, Δ=0.02
```

Surface 绝对值偏移 → `state_formatter` 生成不同文本描述 → LLM context 不同 → 回复口吻不同。

**防御的价值在内容层，不在数值层。**

## 7. 感知层修复

### 7.1 问题

Ollama qwen2.5:7b 在 pilot 中 **100% 失败**：
```
"第 1 次尝试失败: Expecting value: line 1 column 1 (char 0)"
```
模型返回了空字符串或非 JSON 文本，JSON 解析持续失败。

### 7.2 修复

切换为 DeepSeek v4 Pro 做感知提取，精简 prompt：

```python
PERCEPTION_SYSTEM_PROMPT = """你是一个心理刺激提取系统。
分析用户的输入，提取 7 维心理刺激...
不要同时激活多个维度——一段话通常只传达 1-3 种主要信号。
充分使用 [0,1] 全程...
"""
```

### 7.3 效果

| 指标 | Ollama | DeepSeek |
|:----|:------:|:--------:|
| 成功率 | **0%** | **100%** |
| 平均延迟 | ~3s | ~5s |
| 典型输出 | 空字符串 | 结构化的 JSON 刺激向量 |
| 返回非零刺激 | 从不 | 总是 |

DeepSeek 感知返回的实际刺激示例：

```
"月色真美"     → validation=0.4, closeness=0.8 (温暖、被靠近)
"我喜欢你"     → validation=0.9, closeness=0.9, emotional_weight=0.5
"我好像发烧了" → abandonment=0.4, validation=0.3, closeness=0.3
"陪我一会"     → abandonment=0.0, validation=0.2, closeness=0.5, dependency=0.3
```

## 8. 对混合架构假设的验证

### 8.1 假设 1：数学引擎产生不可替代的因果结构

| 证据 | 结论 |
|:----|:------|
| A_full 连续性 0.9996 vs B_scratch 0.6031 | ✅ **证实**——引擎产生了因果连续的状态演化 |
| B_context 即使有上下文仍只达到 0.9249 | ✅ **证实**——纯 LLM 方案即使优化也有上限 |
| LLM 状态极端值率 17.5% vs 引擎 0% | ✅ **证实**——引擎提供了 LLM 没有的"状态约束" |

### 8.2 假设 2：LLM 状态推断可被 prompt 工程改善

| 证据 | 结论 |
|:----|:------|
| B_context 连续性 +53%（0.60→0.92） | ✅ **改善显著**——但产生新偏差 |
| B_context 极端值率激增到 17.5% | ⚠️ **改善有代价**——LLM 倾向情绪饱和 |
| B_context 表面中性率降到 1.4% | ⚠️ **改善有代价**——LLM 从不中性 |

### 8.3 假设 3：防御剖面贡献语义而非数值价值

| 证据 | 结论 |
|:----|:------|
| A_full vs A_no_def 数值指标完全相同 | ✅ **证实**——防御不影响轨迹几何 |
| 回复口吻差异明显 | ✅ **证实**——防御影响内容质量 |

### 8.4 假设 4：混合架构的互补性

数据支持的架构形式：

```
数学引擎 → 状态因果骨架（连续性 + 人格约束）
     ↓
 LLM 表达层 → 自然语言生成（词汇 + 句式 + 修辞）
     ↓
（回复质量高于任何单一方案）
```

这与 `HYBRID_ARCHITECTURE_STRATEGY.md` 的"剧本与演员"类比完全一致。

## 9. 对项目路线的建议

### 9.1 决策树匹配

基于实验数据：

```
A > B_context > B_scratch > C_none
→ 数学引擎确实产生正向边际价值
→ 维持混合架构路线
        ↓
A_full ≈ A_no_def（连续性维度）
→ 防御剖面不是当前瓶颈
→ 重点放在感知精度和状态演化
        ↓
B_context 改善显著但仍有差距
→ LLM 极端化倾向需要约束
→ 可尝试"引擎生成基线 + LLM 微调极端维度"
```

### 9.2 具体建议

1. **维持混合架构路线** — 数学引擎的因果连续性不可替代（Cohen's d=+3.01）

2. **放弃 Ollama 感知** — DeepSeek 100% 成功率碾压 Ollama 0%

3. **简化防御剖面** — 数值层无差异，接口可保留但无需继续优化其数学精度

4. **增加混合推断实验** — 引擎生成基线状态 → LLM 微调极端维度 → 既保持连续性又增加表达丰富度

5. **扩展全量场景** — 20 场景 × 5 条件，特别关注"矛盾信号"类别（口是心非的核心测试场景）

### 9.3 优先顺序

```
P0: 感知层切换为 DeepSeek（已完成验证）
P1: 全量 20 场景 × 5 条件实验
P2: LLM-as-Judge 自动评估（4 维度 × 5 分制 × 3 重复）
P3: 混合推断实验（引擎基线 + LLM 微调）
P4: 时间衰减实验（24h/72h 间隔）
```

## 10. 局限性

### 10.1 已识别局限

| 局限 | 影响 | 缓解 |
|:----|:----|:-----|
| 仅 2 场景 | 结论泛化性有限 | 3/4/5 类别尚未测试 |
| 仅 1 角色 | 仅"月下誓约"一个角色 | 需扩展不同人格配置 |
| 短序列（5 轮） | 无法测试长程一致性 | 需 50+ 轮实验 |
| 无 LLM-as-Judge | 缺少系统性回复质量评估 | 下一阶段添加 |
| Hurst 指数不可用 | 5 个轨迹点不足以计算 | 需 10+ 轮 |
| B_context 的 state_desc 反馈 | 状态注入到生成可能产生循环 | 分离设计已最小化 |

### 10.2 无法回答的问题

1. **长对话（50+ 轮）** 中引擎优势是否扩大？
2. **时间衰减（24h+ 间隔）** 下 LLM 自报是否劣化更快？
3. **不同人格特质**（高回避+高焦虑 vs 低回避+低焦虑）下防御效果是否不同？
4. **数学引擎 vs 无引擎** 的用户感知差异是否显著？

## 附录：实验框架使用说明

### 运行命令

```bash
# Pilot 快速验证
uv run python -m experiment.run --pilot --perception deepseek

# 全量实验
uv run python -m experiment.run --conditions A_full,A_no_def,B_scratch,B_context,C_none --perception deepseek

uv run python -m experiment.analyze experiment/outputs/<tag>_raw.json
```

### 实验框架结构

```
experiment/
├── run.py              # CLI 主入口

├── llm_inference.py    # 条件 B 的 LLM 状态推断

├── auto_metrics.py     # 自动指标计算
├── llm_judge.py        # LLM-as-Judge 框架
└── outputs/            # 结果输出目录
```

### 输出文件

```
experiment/outputs/
├── <tag>_raw.json        # 完整结果（状态轨迹 + 回复 + 刺激）
├── <tag>_analysis.md     # 自动生成的分析报告
└── <tag>.log             # 运行日志
```

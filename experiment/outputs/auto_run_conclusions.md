# 多变量实验深度结论

> **数据**: 2 场景 × 5 条件 | **感知**: DeepSeek (100% 成功率)
> **场景**: 表白回应, 生病照顾

---

## 核心发现

### 发现 1：防御剖面（Bowlby）不影响状态连续性

| 指标 | A_full (完整引擎) | A_no_def (无防御) | Δ |
|:----:|:----:|:----:|:----:|
| 内态连续性 | 0.9996 | 0.9997 | -0.0001 (无差异) |
| 表内分歧度 | 1.4929 | 1.4952 | -0.0023 (无差异) |
| 极端值率 | 0.0% | 0.0% | 0% |

**结论**: Bowlby 防御剖面主要影响**回复的语义内容**（口是心非的程度），而非**状态轨迹的数值特性**。A_full 回复更口是心非（"不许骗人"），A_no_def 更直白（"你知道自己在说什么吗"）。

### 发现 2：状态上下文修复了 LLM 的连续性缺陷（核心发现）

| 条件 | 连续性 | Cohen's d vs 基线 |
|:----:|:------:|:------------------:|
| B_scratch | **0.6031** | —（基线） |
| B_context | **0.9249** | +2.233 (强烈改善) |
| A_full | **0.9996** | +3.012 (数学引擎基准) |

**B_context 将 LLM 自报的连续性从 0.60 提升到 0.92（+53%）**。说明纯 LLM 方案的主要缺陷（跨轮跳跃）可以通过注入上一轮状态信息大幅缓解。

但 B_context 仍低于数学引擎（0.92 vs 0.996），差距约 8%。

### 发现 3：LLM 状态推断有"极端化"倾向

| 指标 | 数学引擎 (A) | LLM 自报 (B) | 差异 |
|:----:|:-----------:|:-----------:|:----:|
| 内态极端值率 | **0.0%** | 17.5-21.3% | LLM 过度使用极端值 |
| 表面中性率 | **45-47%** | 1.4% | LLM 表面从不中性 |
| 表内分歧度 | **1.49** | 2.10-2.32 | LLM 高估表内差距 55% |

**结论**: LLM 在没有数学约束的情况下，倾向于输出情绪饱和的极端状态——每轮感受都强烈，没有"平静"的基线状态。这在长对话中会导致情感疲劳和表达过度。

### 发现 4：各条件的角色保真度（定性）

| 条件 | 回复特征 | 角色匹配度 |
|:----:|:--------:|:----------:|
| A_full | 防御性脆弱、"不许骗人"、嘴硬 | **⭐⭐⭐⭐⭐** 最符合角色 |
| A_no_def | 慌乱直白、"你知道自己在说什么" | ⭐⭐⭐⭐ 略失口是心非 |
| B_context | 浪漫温暖、"我也是一样的" | ⭐⭐⭐ 稀释了tsundere特质 |
| B_scratch | 情感爆发、"等得好辛苦" | ⭐⭐ 完全不符合角色 |
| C_none | 直接回应、"我会当真的" | ⭐⭐⭐ 无明显角色特征 |

## 对混合架构的验证

### 假设 1：数学引擎产生不可替代的因果结构 → ✅ **证实**

```
A_full 连续性:   0.9996  → 因果链完整
B_context 连续性: 0.9249 → 即使有上下文仍有跳跃
B_scratch 连续性: 0.6031 → 几乎随机游走
```

### 假设 2：LLM 状态推断可被 prompt 工程改善 → ✅ **部分证实**

给 LLM 上一轮状态描述使连续性从 0.60 提升到 0.92，但代价是**极端值率从 0% 激增到 17.5%**。prompt 工程改善了连续性但引入了新的偏差（过度情绪化）。

### 假设 3：防御剖面贡献语义价值而非数值价值 → ✅ **证实**

A_full vs A_no_def 的数值指标几乎相同，但回复质量差异明显。防御剖面的价值在**生成的内容层面**，不在**状态轨迹的几何特性**。

## 对项目路线的建议

基于当前数据：

```
决策树匹配:
A > B_context ≈ B_scratch > C_none  → 维持混合架构路线
                        ↓
A_full vs A_no_def 差异小           → 防御剖面不是核心瓶颈
B_context 改善显著但仍有差距        → 优先解决 LLM 极端化倾向
                        ↓
推荐方向:
1. 维持数学引擎作为状态因果骨架（A的连续性不可替代）
2. 可考虑用 LLM 辅助调整极端值（混合推断）
3. 感知层使用 DeepSeek（100% 成功率 vs Ollama 0%）
4. 防御剖面可简化，将资源投入感知精度
```

### 第 2 阶段实验建议

1. **全量 20 场景**验证发现是否泛化
2. **LLM-as-Judge** 对回复质量做系统性评估
3. **时间衰减实验**（24h/72h）测试长间隔下的状态一致性
4. **混合推断**实验：数学引擎生成基线状态 + LLM 微调极端维度
